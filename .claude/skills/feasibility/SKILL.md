# Feasibility

針對使用者正在考慮的想法或方案，找出哪些條件決定它能否成功，並用證據支持判斷。評估範圍隨問題而定：可以是整個提案，也可以是其中一項關鍵風險。

1. **定義問題。** 確認要評估的方案、成功條件、期限、資源及不可變的限制。讀使用者提供的材料和適用的專案規則；缺少會改變結論的條件時先釐清，其餘假設明確標出。
2. **找決定性條件。** 依提案檢查相關面向，例如技術、時間、成本、需求、資料、營運或外部依賴。區分已證實的事實、估計與未知，優先處理最可能推翻方案的風險。對可能變動的外部事實查一手來源。
3. **縮小關鍵未知。** 能低成本、可逆地驗證時，查文件、量測、跑現有測試或做隔離的原型；說明測試能證明什麼、不能證明什麼。需要花費、改變既定限制或執行不可逆動作時，先取得相應授權。
4. **提出判斷。** 給出可行、有條件可行、證據不足或在目前限制下不可行的結論。列出支撐結論的證據、主要剩餘風險、最小下一步，以及哪些新證據會改變判斷。沒有量測依據的數字標為估計。

預設在對話中交付分析；只有使用者要求保存或已授權更新時才寫入文件。發現要求或限制互相衝突時指出衝突並請使用者決定。可行性結論不等於實作授權。

# To Tickets

把已決定的工作切成接手者不依賴當前對話也能完成的票。**票數與迭代方式由工作本身和使用者的限制決定**，不是技能的固定輸出。

1. **確認輸入。** 讀使用者的目標、已定規格、測試或驗收條件、期限、團隊容量與既有票。找出尚未決定、但會改變切法的問題；能從材料查到的事自行查，真正的取捨交給使用者。若使用者已指定票數或分期方式，照它切並指出明顯風險。
2. **提出切法。** 優先按可觀察的成果切成小型縱向切片；必要的環境、遷移或研究工作也可單獨成票，但要說明它解鎖哪個成果。先用最薄的端到端路徑驗證主要接縫，再擴充行為。太大、跨多個獨立成果的票拆開；只能一起驗收的零碎票合併。不要為了符合預設數字拆或湊票。
3. **標依賴。** 每張票只列真正的阻塞邊；「看起來應該先做」不是依賴。把未決問題、外部條件和可平行的票標清楚。
4. **展示全貌。** 先給使用者看票名、可驗收成果、估計大小及依賴圖。若切法涉及優先順序或範圍取捨，讓使用者選定；再依專案既有的 tracker 或檔案慣例建立或更新票。

每張票至少要有：以結果命名的標題、可由他人檢查的完成條件、必要背景與規格連結、阻塞關係。引用既有需求或測試編號時沿用原編號；不要另造一套，也不要複寫整份規格。完成後報告票的路徑或連結、切分理由、依賴與仍待決的問題。

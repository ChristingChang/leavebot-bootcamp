# Implement

完成使用者指定的一張票或一份小型規格。若一次給多項工作，依使用者的優先順序逐項完成；不把技能預設的票數或階段套到專案上。

1. **定範圍。** 讀工作項目及其引用的規格、設計、專案規則與現有程式。列出可觀察的完成條件、關鍵接縫與已存在的測試。衝突或缺少會改變產品行為的決定時，指出問題並請使用者定案。
2. **建置。** 先找現有模式。對可測行為採用適合專案的測試先行循環，一次驗證一個行為；設定、佈線或視覺細節採取相稱的驗證方式。依指定的技術與依賴邊界實作，不為了方便自行改規格。
3. **驗證。** 跑專案要求的測試、型別檢查、lint 或手動流程；以結果核對每個完成條件。依專案追溯慣例更新測試與文件，記錄已確認的偏差。
4. **審查與回報。** 檢查變更是否符合專案標準與工作項目的要求，修正可確認的問題。回報實際完成的行為、執行的檢查與結果、未完成項及原因。提交或推送依使用者的交付要求處理。

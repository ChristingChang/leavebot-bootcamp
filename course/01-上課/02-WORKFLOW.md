## 每階段的節奏
讀卡片與指定檔案 → 叫通用技能並給本課限制 → 產出 → 人依 Gate 審查 → 決策寫檔。
同階段的訪談與寫檔留在同一對話；換階段前確認決策已寫下。每張實作票另開新對話，重新指定票與規格。不要只輸入技能名稱就期待它知道課堂範圍。

卡 H 有兩段，骨架驗收後才使用第二段。卡 J 先分析與定規格，另以 `/implement` 執行變更票。卡 K 先明確指定審查範圍，不使用模糊的「幫我檢查全部」。
Codex 使用相同卡片正文，把開頭技能與文中明確技能呼叫的 `/名稱` 換成 `$名稱`；不要改 API 路徑。換對話與計畫模式使用各工具目前支援的操作。

`docs/01-brief.md`、`02-prd.md`、`03-srs.md`、`04-sad.md`、`05-sds.md`、`06-test-plan.md`；圖在 `diagrams/`（或 SRS 的 Mermaid）；偏差在 `docs/LESSONS.md`。

## 當工具或時間不足
無 Archify 用 Mermaid；無瀏覽器工具由人操作。超過預定進度15分鐘先請講師協助，依 [CHECKPOINTS](../02-補充/02-CHECKPOINTS.md) 確認可用快照，不執行不存在的分支。
核心規則必須清楚，延伸功能不拖住主線；[LEAVEBOT](03-LEAVEBOT.md) 定範圍，[STACK](04-STACK.md) 定技術。題目、模板或講義矛盾時列出差異，由講師處理。

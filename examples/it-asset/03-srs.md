## 1. Use Case

### UC-01 員工申請借用

| 項目 | 內容 |
|---|---|
| 主要角色 | P-01 |
| 前置條件 | 員工已選好身分 |
| 主要流程 | 1. 輸入理由與日期 2. 看到建議類型 3. 選一台設備 4. 系統確認期間可借 5. 送出 |
| 替代流程 | 2a. 建議失敗，員工自己選類型；4a. 期間衝突，顯示衝突日期，回到步驟 3 |
| 結果 | 建立一筆「待核發」的申請 |
| 來源 | US-01、US-02 |

### UC-02 IT 核發與登記歸還

| 項目 | 內容 |
|---|---|
| 主要角色 | P-02 |
| 前置條件 | 有待核發或借用中的申請 |
| 主要流程 | 1. 打開待處理清單 2. 核發 3. 設備歸還時登記歸還 |
| 替代流程 | 無 |
| 結果 | 借用狀態依序變為借用中、已歸還 |
| 來源 | US-04 |

## 2. 功能需求（FR）

| 編號 | 需求 | 來源 | 狀態 |
|---|---|---|---|
| FR-01 | 系統必須依借用理由回傳一個建議類型（laptop 或 projector）與一句理由 | US-01、AC-01.1 | 有效 |
| FR-02 | 建議失敗時，系統必須回傳可讓使用者繼續申請的錯誤訊息 | AC-01.2 | 有效 |
| FR-03 | 系統必須拒絕與既有「待核發」或「借用中」期間重疊的申請，並回傳衝突期間 | AC-02.1 | 有效 |
| FR-04 | 系統必須拒絕歸還日早於借用日的申請 | AC-02.3 | 有效 |
| FR-05 | 系統必須建立狀態為「待核發」的申請 | AC-02.2 | 有效 |
| FR-06 | 系統必須依員工列出其借用與狀態、歸還日 | AC-03.1 | 有效 |
| FR-07 | 借用狀態只能依序 待核發 → 借用中 → 已歸還，不能跳過或倒退 | AC-04.1、AC-04.2 | 有效 |
| FR-08 | 系統必須列出歸還日早於今天且未歸還的借用，並顯示逾期天數 | AC-05.1、AC-05.2 | 有效 |

## 3. 非功能需求（NFR）

| 編號 | 類別 | 需求 | 怎麼驗 | 來源 |
|---|---|---|---|---|
| NFR-01 | 效能 | 建議功能 3 秒內回應，逾時就當失敗處理 | 用會延遲的假 LLM 測逾時路徑 | AC-01.1 |
| NFR-02 | 安全 | 借用理由裡的任何文字，都不能讓系統指定設備、核發或改狀態 | 注入句測試 | G-02 |
| NFR-03 | 失效行為 | LLM 回傳不合格式的內容時，不顯示給使用者也不中斷申請 | 用回傳亂碼的假 LLM 測 | AC-01.2 |
| NFR-04 | 易用性 | 申請頁在 1280px 寬的桌機上不需要水平捲動 | demo 時人工看 | NG-03 |

## 4. 無法驗證區

| 想要的 | 為什麼現在驗不了 | 什麼情況下會變成需求 |
|---|---|---|
| 建議「很準」 | 沒有標註好的借用理由資料 | 收集 30 筆真實理由並標好答案之後 |
